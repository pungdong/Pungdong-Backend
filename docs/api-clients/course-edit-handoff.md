# 강의 수정 — FE 핸드오프

계약의 단일 출처는 [`types.ts`](types.ts) (`CourseCreateRequest` · `CourseResponse` 섹션).
구현/정책은 [docs/architecture/course.md](../architecture/course.md).

**결론부터**: 강의 수정 API 는 **이미 다 있다**. 새로 만들 것 없이 화면만 붙이면 된다.
수강생이 있는 강의도 **수정된다** — 유일한 제약은 *신청 기록이 있는 회차를 없애는 것* 하나뿐이다(§5).

---

## 1. 엔드포인트 (전부 기존)

| 메서드 | 경로 | 용도 |
|---|---|---|
| `GET` | `/courses/mine` | 내 강의 목록 (`_embedded.courses`, `CourseResponse[]`) |
| `GET` | `/courses/{id}` | **편집 화면 prefill** — 강사 전용 원본 |
| `PUT` | `/courses/{id}` | **수정** — body 는 생성과 동일한 `CourseCreateRequest` |
| `PATCH` | `/courses/{id}/status` | `DRAFT` / `OPEN` / `CLOSED` 전환 |
| `POST` | `/course-images` | 이미지 업로드 → `fileURL` (media 에 실을 값) |

전부 인증 필요(`/courses/**` → authenticated). 남의 강의는 **400 `-1009`**(존재 숨김 — 403 아님).

---

## 2. 편집 화면 흐름

실제 순서라서 번호가 의미를 갖는다.

1. **prefill** — `GET /courses/{id}` 로 현재 값을 받아 폼을 채운다.
2. **편집** — 이미지를 새로 올리면 `POST /course-images` 로 먼저 업로드해 `fileURL` 을 받아둔다.
3. **저장** — `PUT /courses/{id}` 에 **전체 객체**를 보낸다.
4. **재조회** — 응답으로 폼 상태를 갈아끼운다. 회차 id 는 유지되지만 미디어 id 는 바뀐다(§3-3).

---

## 3. 반드시 지킬 규칙

### 3-1. PUT 은 부분 수정이 아니라 **전량 교체**다

서버가 요청 body 를 강의의 **새 전체 상태**로 받는다. **빠뜨린 필드는 비워진다.**
제목만 바꾸더라도 rounds·media·extraSession 을 전부 다시 실어야 한다.

> prefill 로 받은 객체를 그대로 들고 있다가 바뀐 필드만 덮어써서 통째로 보내는 방식이 안전하다.
> "변경된 필드만 골라 보내기" 는 **데이터가 지워진다.**

### 3-2. prefill 은 `GET /courses/{id}` — `/detail` 이 아니다

| | `GET /courses/{id}` (강사) | `GET /courses/{id}/detail` (공개) |
|---|---|---|
| 위치 | `venueRefId` 원본 | venue 객체로 합성(이름·주소·입장료) |
| 이용권 | `ticketRef` + `daypart` 원본 | 입장료 금액으로 계산됨 |
| 편집에 쓸 수 있나 | ✅ 그대로 PUT 에 되돌려보낼 수 있음 | ❌ 원본 참조가 없어 되돌려보낼 수 없음 |

`/detail` 값으로 폼을 채우면 저장 시 위치·이용권이 깨진다. **자격증 이미지 `viewUrl` ↔ `fileKey` 와 같은 함정**이다.

### 3-3. `rounds[].id` 는 보존된다 / `media[].id` 는 매번 바뀐다

- **회차 `id` 는 수정해도 그대로다.** (종류, 회차번호)로 기존 행을 찾아 내용만 갱신하기 때문.
  회차를 3개→5개로 늘려도 기존 3개의 id 는 유지되고 뒤 2개만 새로 생긴다.
- **`media[].id` 는 저장할 때마다 새로 발급된다.** 미디어는 전량 교체다(참조자가 없어 안전).
  이미지 목록을 id 로 기억해 두지 말 것.

### 3-4. 검증 규칙 (어기면 400 `-1011`)

- `rounds.length` 가 `totalRounds` 와 **정확히 일치**해야 한다.
- `kind: "CERTIFICATION"` 이면 `organizationCode` + `levels`(1개 이상) **필수**.
  `TRIAL` / `TRAINING` 이면 둘 다 무시된다(서버가 비운다).
- `title` 공백 불가, `totalRounds` 는 양수, `price` 는 0 이상.
- `venueRefId` 는 내 소유 CUSTOM 이거나 존재하는 OFFICIAL 이어야 한다.

## 4. 에러

| 상황 | 상태 | code | 비고 |
|---|---|---|---|
| 검증 실패(회차 수 불일치, 자격 필수값 누락 등) | `400` | `-1011` | `msg` 는 범용 문구 — 필드 특정 안 됨 |
| 없는 강의 / 남의 강의 | `400` | `-1009` | 존재 숨김. 404·403 아님 |
| 미인증 | `401` | — | |
| **신청자 있는 회차를 없애려 함** | `400` | `-1024` | §5. `msg` 를 그대로 노출해도 되는 한국어 문구 |

---

## 5. 수강생이 있는 강의

**대부분 그냥 된다.** 제목·설명·가격·이미지·회차 설명·**회차 위치**·회차 추가 — 전부 수정된다.

막히는 건 **하나**다: **신청 기록이 있는 회차를 없애는 것**.
즉 `totalRounds` 를 줄이거나 추가세션을 빼는데, 사라지는 회차를 이미 누군가 신청한 경우.

| 하려는 것 | 결과 |
|---|---|
| 제목·설명·가격·이미지 수정 | ✅ |
| 회차 설명·위치·이용권 변경 | ✅ |
| 회차 **추가** (3 → 5) | ✅ |
| 회차 **축소** — 없어지는 회차에 신청자 **없음** | ✅ |
| 회차 **축소** — 없어지는 회차에 신청자 **있음** | ❌ `400` `-1024` |

```json
{ "success": false, "code": -1024,
  "msg": "이미 신청한 수강생이 있는 회차예요. 회차를 줄이려면 해당 수강을 먼저 정리해주세요." }
```

`msg` 는 사용자에게 보여줄 용도로 쓴 한국어라 **그대로 노출해도 된다.**

**취소·거절된 신청도 막는다.** 기록이 남아 있으면 그 회차는 지울 수 없다 —
"취소됐으니 괜찮겠지" 로 분기하지 말 것.

### 확정된 학생 예약은 강사 수정으로 움직이지 않는다

강사가 회차의 위치를 바꿔도, 이미 확정된 학생의 예약은 **그대로다**.
수강 기록이 위치·시간을 저장 시점에 스냅샷해 두기 때문이고, 바뀌는 건 *앞으로 잡을* 회차의 후보뿐이다.
그래서 편집 화면에 "학생 일정이 바뀝니다" 같은 경고를 띄울 필요는 없다.

**의도한 동작이다** — 이미 신청한 건 신청한 대로 간다. 특정 학생의 특정 회차 장소까지 정말 바꿔야 하는
상황이면 **그 회차 채팅방에서 강사와 학생이 합의해 푼다**(채팅은 회차 단위다). 강의 편집 화면이
떠안을 일이 아니다.

> 이전 핸드오프에서 안내했던 **`hub?filter=all` 로 편집 버튼을 잠그는 임시 가드는 이제 불필요하다.**
> 넣었다면 걷어내면 된다.

## 6. 상태 전이 (`PATCH /courses/{id}/status`)

```json
{ "status": "OPEN" }
```

- `DRAFT` 임시저장 / `OPEN` 노출중 / `CLOSED` 마감. 검수 절차 없음.
- `OPEN` 으로 올릴 때만 **강사 승인 여부**를 검사한다 — 미승인이면 400.
- 상태 변경은 회차를 건드리지 않으므로 **수강생 있는 강의에도 항상 안전**하다(§5 와 무관).
