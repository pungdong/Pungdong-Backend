> **피처 문서** — 정책·왜·결정 히스토리를 소유한다. 구현(ER·엔드포인트·컴포넌트 맵·권한 매트릭스)은 [docs/architecture/community.md](../architecture/community.md) 로 링크만 하고 복붙하지 않는다.

## 한 줄

다이버들이 투어 자랑·트레이닝·같이가요·궁금해요 네 카테고리로 글을 쓰고 서로 반응하는 **전 role 공용 피드**. 제품 목적은 커뮤니티 자체가 아니라 **퍼널**이다 — 커뮤니티 글에서 강사를 발견하고, 작성자를 눌러 브랜딩 프로필로 들어가고, 거기서 강의로 전환된다.

## 정책

### 1. 모든 글은 커뮤니티 글이고, **프로필에도 남길지만 고른다** 🔴 (2026-08-18 통합)

**브랜딩 글은 따로 있는 게 아니다.** 같은 테이블·같은 폼이고, 다른 건 작성자가 고르는 스위치 하나 — `showOnProfile` 이다.

| `showOnProfile` | 커뮤니티 피드 | 브랜딩 프로필 그리드 |
|---|---|---|
| `false` (기본) | ✅ | ❌ |
| `true` | ✅ | ✅ (= 예전 "브랜딩 글") |

- 작성 경로는 `POST|PUT /community/posts` **하나**다. 구 `POST /branding/me/posts` 는 구버전 앱 호환으로만 남고, 거기로 온 글은 `showOnProfile=true` 와 같은 상태가 된다.
- **프로필에 올리는 건 "더하기" 다.** 커뮤니티 노출을 끄는 수단은 숨김뿐이라, 표현 가능한 공개 상태는 셋뿐이다 — ①커뮤니티만 ②커뮤니티+프로필 ③숨김. **"브랜딩 전용"(커뮤니티엔 안 뜨는 프로필 글)은 만들 수 없고, 이건 의도한 제약이다.**
- **프로필에서 내리기 ≠ 삭제.** `showOnProfile:false` 로 수정하면 그리드에서만 빠지고 글·좋아요·댓글은 그대로 남는다.
- 사진이 0장이면 `showOnProfile` 을 켤 수 없다(400) — 그리드는 사진 타일이라 썸네일 없는 글이 빈 칸이 된다.

**왜 이 방향인가.** 반대(브랜딩 요청에 카테고리·제목을 더해 두 엔드포인트를 유지)로 가면 같은 작성 폼이 분기해 두 계약을 부르고, 필드가 하나 늘 때마다 양쪽을 고쳐야 한다. 테이블이 하나라 서버 비용은 플래그 하나 세팅에 가깝다.

**직전 모델(V19~2026-08-18): "노출은 브랜딩 → 커뮤니티 단방향".** 그때는 *작성 경로*가 플래그를 정했다(브랜딩에서 쓰면 둘 다, 커뮤니티에서 쓰면 피드만). 하이라이트/흐름의 구분 자체는 살아 있고, **누가 그 구분을 정하느냐가 경로 → 작성자로 바뀐 것**이다. 당시 기존 브랜딩 글을 피드에 소급 노출하지 않았던 결정(`show_in_feed=0`)은 V30 에서 되돌렸다 — 대상이 스테이징 내부 테스트 행뿐이었고(프로덕션에는 이 테이블 자체가 없다), 남겨두면 화면에서 설명되지 않는 세 번째 축("숨기지도 않았는데 피드에 없는 글")이 남기 때문이다.

### 1-1. 숨김은 **전역 스위치**다 🔴

어느 화면에서 숨겨도 양쪽에서 숨고, 어디서 풀어도 양쪽이 함께 풀린다(컬럼이 하나다). **"안 보임" 은 남에게만이고 오너는 항상 본다** — 오너 화면에서도 사라지면 그건 숨김이 아니라 삭제다.

| `isHidden` | `showOnProfile` | 커뮤니티 | 브랜딩 그리드 | 오너 |
|---|---|---|---|---|
| false | false | 보임 | 안 보임 | 보임 |
| false | true | 보임 | 보임 | 보임 |
| true | false | 안 보임 | 안 보임 | 상세로 보임 + 숨김 표시 |
| true | true | 안 보임 | 안 보임 | 오너 그리드에 숨김 표시로 남음 |

- **토글 경로도 하나다**: `PATCH /community/posts/{id}/visibility`. 브랜딩 쪽 쌍둥이 엔드포인트는 삭제했다 — 프로필 글만 통과시켜 커뮤니티 전용 글을 못 숨겼고, **어드민 조치(ACTIONED) 확인이 없어 신고로 내려간 글을 작성자가 되살릴 수 있었다**(경로가 둘이면 규칙이 갈린다는 걸 실제로 보여준 사례).
- **되돌릴 화면**: 프로필 글은 브랜딩 오너 그리드에 숨김 표시로 남고, 나머지는 **"내가 쓴 글"(`GET /community/posts/me`)** 에 남는다. 이 목록을 같이 만든 이유가 그것 — 브랜딩 오너 그리드는 프로필 글만 담고 피드는 숨김을 빼서, `숨김 + 커뮤니티 전용` 글은 상세 URL 로만 닿았다. 되돌릴 화면이 없는 숨김은 사실상 삭제다.
- **두 축은 직교한다**: 숨김을 풀어도 프로필로 승격되지 않고(`(T,F)` → 풀기 → `(F,F)`), 프로필에 올려도 숨김이 풀리지 않는다(`(T,F)` → 승격 → `(T,T)`, 남에겐 계속 안 보임). FE 와 합의한 TC 표(H-1~H-6 · P-1~P-4 · C-1~C-3 · Q-1~Q-5)는 `CommunityUseCaseTest` 의 `P*` 그룹 주석에 매핑돼 있고 전부 테스트로 잠갔다.

### 2. "참여 신청" 은 만들지 않는다 — 영구 제외 🔴

같이가요(버디 매칭)에 참여 신청 버튼이 있을 것 같지만 **없다.** 사용자 의도가 명확했다:

> 버디 기능이든 강사 상품연동이든 '신청하기' 는 **강의 수강하기와 동일한 플로우로 예약**하게 되는 걸 의도한 것. 별도로 참여신청 같은 게 있는 건 아니다.

그래서 참여자 테이블도, `appliedByMe` 도, `joinedCount` 도 없다. `capacity` 만 있고 클라이언트는 **"N명 모집"** 으로 렌더한다. **향후 버디 참여를 붙이더라도 커스텀 신청 플로우가 아니라 [예약(booking)](booking.md) 플로우 통합**으로 설계한다.

### 3. 카테고리 4종 고정

`TOUR`(투어 자랑) · `TRAINING`(트레이닝) · `MATCH`(같이가요) · `QNA`(궁금해요).

- **`DIVE_LOG` 를 넣지 않았다** — 회차 다이브로그(수강 기록)와 이름이 충돌해 유저가 두 기능을 헷갈린다.
- **카테고리는 이제 NOT NULL 이다**(V30, 2026-08-18). 두 쓰기 경로 모두 필수로 받고, 기존 행은 `TOUR` 로 backfill 했다. 안 그러면 **오타 하나 고치려는 작성자가 없던 카테고리를 발명해야** 수정이 된다.
  - "없는 값을 지어내지 않는다" 원칙과 충돌하지 않는다: backfill 대상이 실사용자 데이터가 아니다(프로덕션 최종 배포 a383968 에는 V17·V19 자체가 없어 이 테이블이 존재하지 않는다). 값이 `TOUR` 인 건 대상이 전부 **사진 필수였던 구 브랜딩 게시물**이라서다.
  - 구 브랜딩 경로에 `@NotNull` 을 못 걸던 이유(BE 선배포 창 동안 구버전 FE 작성이 400)는 사라졌다 — 신규 작성이 전부 통합 폼으로 가고, 그 엔드포인트는 prod 에서 동작한 적이 없어 되돌아갈 동작이 없다.
- 제목은 **여전히 nullable** 이다 — 구 브랜딩 경로는 제목이 선택이고 그 시절 글이 남아 있다(통합 폼은 2~100자 필수). 클라이언트는 제목 없는 글을 계속 방어해야 한다.

### 4. 같이가요의 영리활동 금지 — 강제 가능한 부분만 강제한다

같이가요는 동료를 구하는 곳이지 강습·투어를 파는 곳이 아니다. 이 중 **기계적으로 판정 가능한 것 하나만** 서버가 막는다: **`MATCH` 글에는 강의를 연결할 수 없다**(400).

본문 광고는 판정하지 않는다 — 오탐 비용이 크다. 그쪽은 `ReportReason.COMMERCIAL` 신고 → 어드민 처리 경로로 간다.

### 5. 신고는 접수 + 어드민 수동 처리 (2-A)

자동 숨김 임계값 없음. **조직적 신고로 정상 글이 사라지는 위험이 어드민 부재 시간대의 노출보다 크다**고 판단했고, 임계값 튜닝은 실데이터 없이는 감이다. 어드민이 `ACTIONED` 로 바꾸면 **대상이 실제로 숨겨진다**(상태만 바뀌고 콘텐츠가 살아 있으면 조치가 아니다). 중복 신고는 에러가 아니라 **200 멱등**, 자기 콘텐츠 신고는 400.

### 6. 알림은 댓글 1종뿐, 기존 NOTICE 채널 재사용

**새 알림 채널을 만들지 않았다** — 채널 추가는 앱 릴리스에 묶여서 구버전 앱이 모르는 채널을 못 그린다. 수신자는 **언제나 최대 1명**(답글→부모 작성자, 댓글→글 작성자)이고, **자기 알림은 발행하지 않는다**(내 글에 내가 댓글 다는 건 흔한 동작이라 안 막으면 소음이 쏟아진다).

좋아요·북마크 알림은 없다. 있으면 가장 시끄러운 알림이 된다.

### 7. 화면 정책

- **모바일 탭 5개로 확장** — 홈·일정·커뮤니티·수강관리·프로필. 커뮤니티 탭은 **전 role 공통**(강사도 들어온다).
- **브랜딩 화면에는 좋아요·댓글 UI 를 노출하지 않는다**(D12). 같은 글이라도 하이라이트 맥락에서는 소셜 액션을 걸지 않는다.
- **카테고리 진입 화면은 Phase 1 범위 밖** — 메인 피드의 `?category=` 필터로 대체(D16). 이 화면이 빠지면서 고아가 된 UI 요소가 4개 있었고(참여 신청 버튼 · `participatedByMe` 필터 · `SOONEST` 정렬 pill · 모집중/마감 뱃지), 전부 추적해 정리했다. **`SOONEST` 는 enum 에 죽은 값으로 남기지 않고 `?category=MATCH` 의 서버 기본 정렬로 살렸다.**
- **댓글 정렬은 서버 고정** — 디자인의 "최신순 ▾" 은 다른 옵션이 정의된 곳이 없어 정적 라벨로 처리한다(FE 가 chevron 미렌더).
- **지난 모집글은 흐리게** — 모집중/마감 뱃지 대신. `open` 은 파생값이라 비용이 없다.

### 8. 강사 글 필터의 판정 축

웹 피드의 "강사 글" pill(`?authorType=INSTRUCTOR`)은 **승인된 강사 신청**을 기준으로 거른다 — 작성자 칩(`isInstructor`)과 **같은 축**이다. 칩과 필터가 다른 축을 쓰면 "강사 글만" 을 눌렀는데 칩 없는 글이 섞이는, 설명할 수 없는 화면이 나온다. (코스 소유는 이 축이 아니다 — [강사 판정 갭](../architecture/community.md) 참고.)

### 9. 범위 밖 (Phase 1 에서 만들지 않음)

영상 · 팔로우 · 핫 토픽 · 임시저장 · 검색 · 알림 아이콘 · 차단 · 투어 상품 연결 · handle 표기. 공유는 클라이언트 시트로 처리(서버 관여 없음).

**같은 실수가 네 번 났고, 규약이 못 잡는 종류가 하나 있었다.** 토글 shape · 댓글 비페이징 · `sort` · `authorType` 이 전부 "문서와 구현이 갈라짐" 인데, 앞의 셋은 *코드를 고치며 문서를 안 고친* 것이라 per-PR 규약으로 잡히지만 **`authorType` 은 문서에만 있고 코드가 없던 것**이라 고칠 코드가 없어 규약이 작동하지 않았다. Spring 이 모르는 쿼리 파라미터를 조용히 무시하는 탓에 **에러조차 나지 않았다**(눌러도 전체 글이 나오는 "필터가 걸린 척").
→ 그래서 **계약의 파라미터 표를 실제 서버에 한 줄씩 때려보는 검증**을 Phase 5 완료 조건에 넣었다. 존재하지 않는 파라미터를 **대조군**으로 함께 던져, "200 이 왔으니 동작한다" 가 아니라 **"결과가 대조군과 다른가"** 로 판정한다.

### 구현 중 잡힌 실버그

- **커뮤니티 글이 브랜딩 프로필 그리드로 샜다** — 공유 테이블에 노출 축을 얹으면서 브랜딩의 기존 조회 3곳(`findPublicGrid`·`findOwnerGrid`·게시물 수 카운트)을 함께 고쳐야 했다. use-case 테스트 X1/S2 가 잡았다. **새 축을 더하는 변경은 그 테이블을 읽는 모든 경로 목록을 먼저 만들고 시작해야 한다.**
- **`{"instructor":false,"isInstructor":false}` 이중 직렬화** — Lombok 이 만든 `isInstructor()` 게터의 암묵 프로퍼티명과 필드명이 갈라져 두 키가 나갔다. 필드명을 `instructor` 로 맞추고 `@JsonProperty("isInstructor")` 를 병기해 해결.

## 미해결 / 확장

- 🟡 **강의 연결의 "강사만" 이 계약만큼 강하지 않다** — 서버가 보는 건 코스 소유권뿐이고 `POST /courses` 는 `authenticated()` 다. 좁히려면 [코스 도메인](course-create.md)의 결정이 먼저. 실위험은 낮다(코스를 만들 동기가 있는 사람은 사실상 강사).
- ✅ **DRAFT 강의 연결** — "거르지 않고 **선택 시점 + 선택 후 두 번 고지**" 로 확정(2026-08-11). 서버는 막지 않는다(준비 중인 강의를 미리 걸어두는 건 유효한 사용). 시트·드롭다운은 닫히면 안 읽혀서 폼에도 안내가 남아야 한다는 게 결정의 근거다. `CLOSED` 는 거르지도 고지하지도 않는다.
- 🟡 **레이트리밋 미구현**(D6) — 글·댓글 연타. 좋아요·북마크·신고는 UNIQUE 로 멱등이라 안전하지만 글·댓글은 아니다.
- 🟡 **댓글 스레드 크기 상한 없음** — 수백 개가 쌓이면 최상위만 페이징으로 켠다(대댓글은 계속 인라인).
- 🟢 **`POPULAR` 튜닝** — 최근 7일 + 좋아요 desc 고정. 댓글 수를 안 본다.
- 🟢 **검색·핫 토픽·팔로우** — Phase 2 후보.
- 🟢 **자동 숨김 임계값** — 신고량이 늘면 `auto_hidden_at` 컬럼 하나로 얹을 수 있게 스키마를 열어 뒀다.
