# OTA 텔레메트리 · 릴리스 대시보드 · 앱 최소버전 게이트

> **무엇을 / 왜 — 정책과 결정 히스토리.** *어떻게*(컴포넌트·흐름·ER·권한 매트릭스)는
> [docs/architecture/ota.md](../architecture/ota.md). 앱 쪽 아키텍처(번들·채널·지문·롤백 메커니즘)는
> PungDong 레포 `docs/features/ota.md`.
>
> 걸치는 도메인: `ota`(BE 신규) · `account`(탈퇴 익명화·유저 링크) · 모바일 앱 · `apps/admin`.

## 왜 이게 필요한가

Hot Updater 에는 **CodePush 식 릴리스 대시보드가 없다.** 워커는 무상태이고 D1 에는 번들 메타만 있다.
그래서 "잘못된 번들이 나갔을 때 **몇 명이 어디 있나**" 를 답할 수단이 아무 데도 없었다.

그런데 OTA 의 실패 모드는 **조용하다** — 앱은 켜지고, 스토어 빌드는 통과하고, 아무도 새 번들을 못 받는다.
관측이 없으면 그 상태를 며칠씩 모른다. 이 트랙은 그 빈칸을 우리 BE 의 기기 테이블로 메운다.

여기에 **최소버전 게이트**가 함께 온다. OTA 는 JS 만 바꾸므로 네이티브가 바뀐 릴리스 이후엔 구버전 바이너리
사용자를 스토어로 유도할 수단이 없다 — 그게 `GET /app/policy` 다.

## 결정 로그 (추가만, 삭제 X)

### D1. 저장소 = 새 `ota_device` 테이블 (`firebase_token` 확장 아님) — 사용자 결정 2026-08-17

원래 이슈(#278)는 기존 디바이스 테이블(`firebase_token`)에 컬럼을 얹자고 했다. **기각했다.**

그 테이블은 "설치된 앱"이 아니라 **"푸시 토큰"의 수명**을 산다:

| 언제 | 무슨 일 |
|---|---|
| 로그아웃 | 행이 **삭제**된다 (`useLogout` → `DELETE /me/devices/{token}`) |
| 탈퇴 익명화 | 계정의 모든 행 **하드삭제** |
| 푸시 권한 거부 | 애초에 행이 **없다**(FCM 토큰을 얻은 뒤에만 등록한다) |
| 비로그인 | 마찬가지로 없다 |

즉 카운트가 "로그인 + 푸시 허용 기기"만 세게 되고, 에픽 완료 기준("카운트가 실제 기기 수와 맞는다")을
정의상 못 맞춘다. **그리고 그 어긋남은 조용하다** — 화면은 정상으로 보이고 숫자만 작다.

결정적인 논거는 방향이다: **"잘못된 번들에 갇힌 사용자"는 앱이 이상해서 로그아웃했을 가능성이 오히려 높다.**
즉 `firebase_token` 확장은 **가장 보고 싶은 집단을 우선적으로 지운다.**

→ 앱이 만든 `installId` 를 키로 하는 독립 테이블 + **permitAll 수집**. 로그인·푸시 권한과 무관하게 모든 설치가
잡히고, 로그인 이력이 있으면 `account_id` 가 남아 CS 드릴다운도 된다(로그아웃해도 유지).

### D2. `installId` 는 UUID 를 강제하지 않는다

RN(Hermes)에는 WebCrypto 가 없어 앱은 **암호학적 난수** UUID 를 만들 수 없고, 폴리필을 넣으면
**지문이 바뀌어 이 트랙 전체가 OTA 배포 불가**가 된다. 앱은 `Math.random()` 기반 uuidv7 *레이아웃* 문자열을
쓰고, BE 는 길이(≤64)와 **안전 문자셋**만 본다.

`@Pattern` 이 있는 건 형식 강제가 아니라 **안전 한계**다 — permitAll 경로변수로 들어오므로 `/`·CRLF·공백을 막는다.
(같은 이유의 선례: `packages/api-client/src/clientMessageId.ts`.)

> 🔒 **불변조건**: `installId` 는 예측 가능한 값이므로 **인증 수단이 아니다.**
> 이 값을 키로 하는 **비인증 읽기** 엔드포인트를 절대 추가하지 않는다(예: "내 기기 상태 조회").
> 지금은 비인증 경로가 쓰기 전용이고 읽는 경로는 ADMIN 뒤에 하나뿐이라 안전하다.

### D3. 관측은 관용적으로, 제어는 엄격하게

**앱은 4xx/5xx 를 전부 삼키고 재시도하지 않는다.** 그래서 텔레메트리에서 거절은 곧 **"그 기기가 영구히 집계
밖"** 이고, 그 손실은 아무 신호도 남기지 않는다. 그래서:

| | 정책 | 예 |
|---|---|---|
| **관측**(텔레메트리) | 받을 수 있는 건 받고 **못 쓰는 값만 조용히 버린다** | `appVersion` 은 `1.0`(2자리)도 허용 · `fingerprintHash` 형식 미검증 · 크래시 이력의 잘못된 원소만 폐기 |
| **제어**(정책 입력) | **엄격**. 사람이 폼에 넣고 에러가 화면에 보이며, 틀린 값이 게이트를 잘못 여닫는다 | `PUT /admin/app/policy` 의 semver 는 3자리 고정 |

같은 semver 인데 두 곳의 규칙이 다른 건 **의도된 비대칭**이다. "규칙이 두 군데 다르네, 통일하자"로 §관측 쪽을
엄격하게 만들면 조용한 영구 이탈이 되살아난다.

구체적 사례:
- `fingerprintHash` 를 40자 hex 로 못 박으면, 라이브러리가 SHA-256(64자)으로 바꾸는 날 **전 기기가 텔레메트리에서
  사라진다.**
- `appVersion` 을 3자리로 못 박으면, 누가 한 번 `1.0` 으로 올린 순간 **그 빌드의 전 기기가 영구히 400** 이다
  (iOS 의 `CFBundleShortVersionString` 은 2자리가 완전히 합법이다).
- 크래시 이력은 스스로 **보조 신호**인데, 원소 하나 때문에 400 을 내면 `appVersion`·`otaBundleId` 같은
  **주 신호까지 통째로 버려진다.**

### D4. 롤백은 2종이고, 합치면 운영 루프가 자기 자신을 트리거한다

| | `SERVER_ROLLBACK` | `CRASH_ROLLBACK` |
|---|---|---|
| 원인 | 어드민이 **disable / rollout 인하** (정상 운영) | 번들이 첫 렌더 전 앱을 죽임 (**사고**) |
| 앱 신호 | `onUpdateProcessCompleted({status:'ROLLBACK'})` | `onNotifyAppReady({status:'RECOVERED', crashedBundleId})` |
| 어드민 의미 | "내가 누른 게 먹었다" 확인 | 🚨 빨간불 |

합치면 **disable 을 누른 직후 숫자가 치솟아** "번들이 터졌다"처럼 보이고, "롤백이 오르면 disable 한다"는 운영
루프가 **자기 자신을 트리거**한다. 특히 **rollout 인하는 신규 배포 중단이 아니라 이미 받은 기기의 즉시 강제
회수**라(모든 ROLLBACK 이 force 로 덮어써지고 앱이 그 자리에서 리로드된다), 정상 조작 한 번이 대량 이벤트를 만든다.

### D5. `DOWNLOADED` 는 다운로드 **완료**다

이슈 #278 이 제안한 `onUpdateProcessCompleted → downloaded` 매핑은 **틀렸다** — 비강제 경로에서 그 콜백은
다운로드 *시작* 시점에 즉시 불려서 **실패한 다운로드까지 집계된다.** 완료 신호는 `onProgress` 의
`progress === 1`(부팅 경로) / `checkForUpdate()` 반환값(포그라운드 재체크 경로)이다.

### D6. `crashRollbackReportedAt` — 이름으로 막는다

크래시는 **이전 실행**에서 났고 네이티브가 롤백한 뒤 **다음 부팅**에 보고된다. 사용자가 3일 뒤 앱을 켜면 3일 뒤
타임스탬프가 찍힌다. 실제 크래시 시각은 **네이티브가 주지 않아 관측 불가**라 서버 수신 시각이 최선인데,
`crashRollbackAt` 이라고 부르면 어드민이 그걸로 타임라인을 그려 **"배포 3일 뒤 크래시"** 로 렌더한다.
→ 이름에 `Reported` 를 넣어 그 사실을 드러낸다. `downloadedAt`·`serverRollbackAt` 은 즉시 전송이라 그대로 둔다.

### D7. 숫자의 의미를 화면이 말하게 한다

관측 지표는 이름만 보면 다들 조금씩 틀리게 읽힌다. 그래서 **카운트 정의표를 단일 출처로 두고 어드민 툴팁이
그대로 쓴다**(아래 §카운트 정의). 응답에 `activeWindowDays` 를 실어 내리는 것도 같은 이유다.

### D8. 완료 기준 문언 정정 3건 (2026-08-17)

| 원문 | 정정 | 이유 |
|---|---|---|
| "카운트가 **실제 기기 수**와 맞는다" | **활성 설치 수(최근 7일)** | `installId` 는 재설치 시 재발급이라 물리 대수와 1:1 이 아니다(설계 성질, 결함 아님) |
| "disable 하면 **다음 실행에** 이전 번들로 돌아간다" | **즉시 리로드** | 모든 ROLLBACK 은 force 로 덮어써지고 `reloadOnForceUpdate` 기본값이 true — 검수는 disable 직후 그 실행에서 하면 된다(오히려 쉬워진다) |
| 최소버전 게이트를 OTA 로 배포 | **다음 스토어 빌드부터 유효** | 게이트 화면은 JS 라 OTA 로 나가지만, 구 지문 바이너리에는 애초에 그 번들이 안 간다 |

## 카운트 정의 (단일 출처 — 어드민 툴팁이 그대로 쓴다)

| 이름 | 정의 | 윈도우 | 반드시 알아야 할 것 |
|---|---|---|---|
| `active` | 그 번들로 최근 N일 안에 **부팅하거나 앱을 포그라운드로 되돌린** 기기 | ✅ | "지금 실행 중"은 **관측 불가**다 |
| `installed` | 마지막 보고 시점에 그 번들을 실행 중이던 기기 | ❌ | 🔴 **누적이 아니다** — 다른 번들로 넘어간 기기는 빠진다. `active ⊆ installed` |
| `downloaded` | 그 번들을 받은 기기 전부 | ❌ | ⚠️ **설치까지 끝낸 기기도 포함**한다 |
| `downloadedNotInstalled` | 받았는데 아직 안 켠 | ❌ | 에픽이 지목한 핵심 지표. `downloaded` 의 부분집합 |
| `serverRolledBack` | disable/rollout 인하로 정상 복귀 | ❌ | 알람 대상 아님. **정상 조작만으로 대량 발생**한다(무채색 표기) |
| `crashRolledBack` | 컬럼 일치 **또는** 크래시 이력 배열에 포함 | ❌ | 🚨 **사실상 단조 증가**(기기당 20회 초과 시에만 예외) + **항상 하한** |

**모수의 한계** — 어드민 화면에 배지로 노출할 것:
- 모수는 "부팅 보고를 보낸 기기"다. Debug 빌드·`__DEV__`·네트워크 실패 기기는 빠진다.
- 비로그인·푸시 거부 기기는 **포함**된다(D1 결정의 이득).
- 재설치는 새 행이 되므로 **"활성 설치 수"이지 "실물 대수"가 아니다**.
- `crashRolledBack` 은 **기기가 다시 켜져야 보고된다** — "0 이니까 안전"이 아니다.

## 역할 분담 — BE 는 D1 을 읽지 않는다

| 무엇 | 어디가 소유 |
|---|---|
| 기기 카운트·기기 목록·앱버전/지문 분포 | **BE**(`/admin/ota/**`) |
| 번들 메타(메시지·커밋·enabled·rollout·force·플랫폼·지문·배포시각) | **Cloudflare D1** — 어드민이 in-process 로 읽음 |
| 조작(enable/disable·rollout·force·삭제) | **D1 직결**(어드민 Server Action). BE 엔드포인트 없음 |
| 앱 최소버전 정책 | **BE**(`app_policy` 단일 행) |

**왜 BE 가 D1 을 안 읽나**: 라이브러리 D1 스키마가 8개월에 두 번 바뀌었다(0.29 `rollout_cohort_count`/
`target_cohorts`, 0.31 `manifest_*`/`bundle_patches`). 컬럼명을 Java 에 새기면 라이브러리 업그레이드가 곧
**사일런트 데이터 손상**이고 타입체크로 못 잡는다. 어드민 쪽은 TS 라 최소한 컴파일이 깨진다.

**조인 규약**(어드민 RSC): `bundleId` 문자열 키 조회(`toLowerCase()` 방어). BE `IOS`/`ANDROID` ↔ D1
`ios`/`android` 변환은 어드민 몫. **D1 에 있는데 BE 에 없으면** = 아직 아무도 안 받은 새 번들(zero-fill 로 0).
**BE 에 있는데 D1 에 없으면** = **삭제된 번들에 갇힌 기기** — 이 기능의 목적상 가장 놓치면 안 되는 집단이라
대시보드에 별도 섹션으로 표시한다(그래서 `bundle-stats` 에 전량 모드가 있다).

## 앱 최소버전 게이트 — fail-safe 방향이 반대다

- 정책 행이 **없으면** `minVersion "0.0.0"`(전 버전 통과)으로 응답한다. 시드 행은 넣지 않는다.
- 앱도 조회 실패(오프라인/타임아웃/5xx)를 **통과**로 처리한다.
- `SiteSettings`(런칭 게이트)는 "사고 시 잠그는" 쪽이 안전하지만 **앱 정책은 "사고 시 여는" 쪽이 안전하다** —
  게이트가 사용자를 앱 밖에 가두면 안 된다.

> 🚨 **`GET /app/policy` 는 어떤 경우에도 401 을 내지 않는다.** 앱은 공개 엔드포인트도 **같은 axios 인스턴스**로
> 부르는 관례라 토큰이 동봉되는데, 401 이 한 번이라도 나오면 그 인스턴스의 인터셉터가 `setUnauthenticated()` 를
> 호출해 **부팅 중에 정상 사용자가 강제 로그아웃**된다. 실제 리스크는 **만료 토큰이 붙어 왔을 때**이고,
> `AppPolicyUseCaseTest` P3 가 그걸 잠근다.
