# 브랜딩 페이지 / 내 프로필 (account-branding)

> 여러 도메인(account · instructorapplication · course)에 걸친 **교차 피처**. 이 문서는 *정책·왜·결정 히스토리*를 소유한다. 구현(ER·엔드포인트·매처)은 [docs/architecture/branding.md](../architecture/branding.md).

## 한 줄

강사에겐 **"브랜딩 페이지"**, 일반 유저에겐 **"내 프로필"** — 같은 스키마·같은 엔드포인트를 쓰고 **워딩과 응답 필드만 role 로 갈린다.** 자기표현으로 커뮤니티 활동·수강 유도·버디매칭을 잇는 게 목적이다.

## 정책

### 강사 전용이 아니다
일반 유저도 같은 기능을 쓴다. 강사 한정 요소만 빠진다 — **자격 뱃지·종목·강의 연결·수강생 수·검수 배너·인증마크**. 응답에서 그 키들은 **아예 생략**되고 FE 가 `undefined` 로 분기한다.

### "없음"이 두 종류다
- **Phase 2 미구현 필드**(평점·후기·팔로워·주간조회) → **키 생략**
- **유저가 지운 값**(tagline·bio·활동지역) → **`null` 명시**

둘 다 생략하면 FE 가 편집 화면에서 "아직 안 만든 것"과 "유저가 지운 것"을 구분 못 해 덮어쓸지 판단이 안 선다.

### 프로필은 모든 계정에 있다 (기본 프로필, 2026-08-21)

**프로필은 계정의 성질이지 따로 만들어야 생기는 물건이 아니다.** `account_branding` **행이 없어도 `GET /instructors/{nickName}` 은 200** 이고, 비어 있는 프로필이 나간다.

**왜.** 페이지에 실리는 값 중 그 행이 실제로 소유하는 건 tagline·bio·활동지역·공식기록·게시물뿐이다 — 닉네임·아바타는 `account`, 인증마크·자격은 `instructorapplication`, 강의 수는 `course` 소유라 **행이 없어도 빈 프로필은 완전하게 계산된다.** 행은 "이 사람이 뭔가 적었다"는 사실의 저장소일 뿐 페이지의 존재 조건이 아닌데, 그 둘을 같은 것으로 취급해서 "안 적었으면 페이지도 없다"가 되어 있었다.

**실제로 새던 곳.** 글을 쓰면 브랜딩 행이 upsert 되지만 **댓글은 안 된다**(`CommunityCommentService`). 그런데 댓글 응답에도 작성자 닉네임이 실리고 그 계약이 "클라이언트가 `GET /instructors/{nickName}` 으로 그대로 쓴다" 였다 → **댓글만 단 유저를 클릭하면 400.** 강의 상세의 강사(프로필을 만든 적 없는 강사)도 같은 증상이었다.

**가입 시 행을 미리 만드는 방식은 쓰지 않았다.** 전 계정에 빈 행 + 백필 마이그레이션 + 경합이 따라오고, 무엇보다 "조회는 생성하지 않는다"는 아래 규칙을 흔들 유혹이 생긴다. 파생으로 답하면 쓰기가 전혀 없다.

**뒤집은 전제를 명시해 둔다.** 기존 설계의 근거는 "첫 쓰기 시점엔 이미 내용이 있으니 **빈 페이지가 공개될 일이 없다**" 였고, 이 결정은 그걸 의도적으로 뒤집는다. 근거는 이미 커뮤니티 피드·강의 상세에서 그 사람의 **닉네임·아바타·강사 칩이 공개되고 있다**는 것 — 빈 프로필은 새 정보 노출이 아니라 이미 공개된 정보의 착지점이다. 프로필이 카드보다 적게 보여줄 이유가 없다.

**그래도 400 인 셋** (`PublicProfileResolver`):
1. 그 닉네임의 살아있는 계정이 없다 (없는 닉네임 · 탈퇴)
2. 행이 있고 **유저가 직접 비공개로 내렸다**(`is_published=false`) — "안 적었다"와 구분된다. 예전엔 둘 다 400 으로 뭉개져 있었다
3. 상대가 나를 차단했다 (내가 차단한 경우는 200 + `blockedByMe` — 유일한 해제 동선)

⚠️ **닉네임 중복 시 tie-break 이 바뀌었다.** 예전 쿼리는 "그 닉네임을 가진 **발행된 프로필** 중 가장 오래된 계정" 이었고 지금은 "그 닉네임의 **살아있는 계정** 중 가장 오래된 것" 이다. 모두에게 페이지가 있는 이상 "발행한 쪽을 고른다"는 규칙은 성립하지 않는다. `account.nick_name` 에 UNIQUE 인덱스가 붙으면 사라질 문제이고, 그걸 서두를 이유가 하나 늘었다.

### 조회는 생성하지 않는다
> **게시물 작성·숨김은 이제 커뮤니티가 소유한다(2026-08-18).** 두 화면의 관계 규칙(진리표·소유권 분할·함정)은 [features/post-surfaces.md](post-surfaces.md) 가 단일 출처다. 프로필 그리드에 뜨는 글도 커뮤니티 글이고, 작성 폼은 `POST|PUT /community/posts` 하나다(`showOnProfile: true` 가 프로필 그리드까지 올린다). 숨김도 `PATCH /community/posts/{id}/visibility` 하나 — 브랜딩 쪽 쌍둥이 엔드포인트는 삭제했다. 정책은 [features/post-surfaces.md](post-surfaces.md), 구현은 [architecture/branding.md](../architecture/branding.md) 권한 매트릭스.

별도 생성 엔드포인트가 **없다.** 첫 쓰기(프로필 편집 / 첫 게시물 작성)가 곧 생성이다. 디자인상 "신규" 상태의 CTA 가 `첫 게시물 작성하기` 하나뿐이고 "프로필 만들기" 단계가 없기 때문이며, 무엇보다 **GET 에 side effect 를 넣지 않는다**(프리페치·재시도·캐시가 전부 쓰기를 유발한다). 생성 시 `is_published = true` — 그 시점엔 이미 내용이 하나는 들어 있어 빈 페이지가 공개될 일이 없다.

### 발행에 승인 게이트가 없다
누구나 발행할 수 있다. **인증마크만** 승인된 강사에게 붙고, 검수 배너는 **강사 신청 이력이 있는 오너**에게만 렌더된다(일반 유저에겐 검수 개념이 없다).

### 공개 URL 은 닉네임
순차 id 를 공개 URL 에 노출하면 열거로 전수 스크래핑이 된다(루트 CLAUDE.md anti-IDOR). 전용 `handle` 컬럼 신설안이 있었으나 **닉네임을 쓰기로 결정**했다(D3) — 대신 닉네임에 형식 가드·예약어 차단·유일성이 필요해졌다. **닉네임 변경 시 공유 링크가 깨지는 것은 감수**한다(필요해지면 handle 컬럼 추가 + backfill + 리다이렉트로 이행).

### 자격은 자유입력하지 않는다
디자인은 자유 텍스트 chip("CMAS ★★★", "KUDA 정회원")이었으나, **다이빙에서 허위 강사 자격은 안전 문제로 번진다.** 그래서 Phase 1 은 **승인된 강사 신청에서 파생한 `certs` 만** 내려주고, 자유입력 편집 API 와 테이블은 폐기했다. 자유 자격은 추후 **어드민 승인제 "자격증 관리" 피처**가 담당한다.

### 영상은 넣지 않는다
스키마에 `kind(PHOTO|VIDEO)` **자리만 예약**하고 업로드는 거부한다. 근거·패턴별 난이도는 GitHub 이슈 [#207](https://github.com/pungdong/Pungdong-Backend/issues/207) 로 이관(강의 등록 영상과 묶어 별도 트랙). 요지: 트랜스코딩·큐 인프라가 전무하고 Fargate 0.5vCPU/1GB 에서 트랜스코딩하면 API 가 같이 죽으며, **디자인에도 영상 전용 화면이 0개**라 FE 도 현 상태로는 구현할 수 없다.

## 미해결 / 확장

- 🔴 **`account.nick_name` UNIQUE 인덱스 + 중복 dedupe** — 공개 URL 식별자인데 DB 유일성이 없다. dedupe 는 유저에게 보이는 식별자를 바꾸므로 **실데이터 사전 점검·승인 후** 별도 마이그레이션으로 간다. 현재 인프라에 prod 읽기 경로가 없다는 것도 함께 풀어야 한다(ECS Exec 비활성 + 런타임 이미지에 mysql 클라이언트 없음).
- 🔴 **`/`·`\` 가 든 기존 닉네임은 프로필이 열리지 않는다** — Spring Security 방화벽이 거부. 방화벽은 풀지 않고 리포트 후 개별 안내.
- ✅ **닉네임 형식 가드·예약어 차단** (2026-08-19) — `global/validation/NickNamePolicy` 단일 출처. 2~16자 한글·영문·숫자·밑줄 + 예약어(브랜드 '풍덩'·운영자 역할어·라우트어) 차단이 가입·변경·중복확인 세 경로에 걸린다. 정책·결정 히스토리는 [features/nickname.md](nickname.md), 구현은 [architecture/sign-up.md](../architecture/sign-up.md) '닉네임 정책'. ⚠️ **기존 계정은 재검증하지 않는다** — 이미 `public` 등을 가진 계정은 audit 리포트로 잡아 개별 안내.
- 🟡 **게시물·기록 편집·파생 통계** — 후속 PR.
- 🟡 **수강생용 화면 디자인 부재** — 일반 유저에게 열기로 했으나 전용 artboard 가 없다. 강사 화면에서 강사 한정 요소를 뺀 형태로 시작한다.
- ⚪ **Phase 2 소셜** — 좋아요·댓글·팔로우·찜하기·조회수·DM. 커뮤니티 피처와 묶어 진행.
