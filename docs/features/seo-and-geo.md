# 검색·생성엔진 노출 (SEO / GEO) — BE 가 지는 몫

> 피처 문서 — **정책·왜·결정 히스토리를 소유**. 구현(게이트·필드·ER)은 도메인 문서로 링크만(복붙 X, drift 방지).
>
> 짝 문서는 **FE 레포의 [`docs/web-seo.md`](https://github.com/pungdong/PungDong/blob/master/docs/web-seo.md)** — 그쪽이 sitemap·robots·메타데이터·JSON-LD 를 소유한다. 이 문서는 **그 구조가 서 있으려면 BE 응답이 무엇을 보장해야 하는가**만 다룬다. 무엇이 누구 결정인지는 아래 §소유 경계.

## 한 줄

공개 웹(`www.plop.cool`)에서 **강의·강사·커뮤니티 글 URL 은 판매 화면이기 전에 색인 자산**이라는 전제를 BE 계약에 반영한 것 — ① 마감된 강의 상세를 읽기 전용으로 열어 **URL 이 죽지 않게** 하고, ② 목록 응답에 `updatedAt` 을 실어 크롤러가 **바뀐 것만** 다시 가져가게 하고, ③ 공개 응답이 **사실을 문자열이 아니라 구조로** 담아 검색엔진과 생성엔진이 둘 다 읽을 수 있게 한다.

## SEO 와 GEO 는 다른 게임이다 (섞으면 판단이 흐려진다)

| | **SEO** — 검색엔진 | **GEO** — 생성엔진(ChatGPT·Perplexity·Claude) |
|---|---|---|
| 목표 | URL 이 **발견**되고 **재방문**된다 | 우리 사실이 **인용**된다 |
| 성공 | 검색 결과에 뜬다 | 답변 안에 우리 이름·가격·조건이 들어간다 |
| 실패 모드 | 404 로 자산 증발 · 크롤 예산 낭비 | **모순되거나 뭉개진 사실** → 인용 자체를 안 한다 |
| BE 가 지는 몫 | 게이트(무엇이 200 인가) · `lastmod` 원천 시각 | **응답이 사실을 구조로 담고 있나** · 두 표면의 사실이 안 갈리나 |
| FE 가 지는 몫 | sitemap · robots · canonical · ISR | JSON-LD · 본문이 JS 없이 읽히나 |

**둘의 교집합이 크다** — 죽지 않는 URL 과 정확한 사실은 양쪽 모두에 필요하다. 그래서 문서가 하나다. 다만 **판단이 갈릴 때는 축을 구분해야 한다**: 예컨대 "마감 강의를 sitemap 에 넣을까" 는 순수 SEO 판단(크롤 예산)이고, "가격을 `35만원` 문자열로 내려줄까" 는 순수 GEO 판단(사실의 구조화)이다.

## 왜 BE 가 이걸 신경 쓰나 — 웹은 앱이 아니다

앱에서 "판매 중이 아닌 강의를 숨긴다" 는 옳다. 웹에서는 같은 동작이 **자산을 태운다**:

- 색인된 URL 이 404 가 되면 그 페이지가 수 주에 걸쳐 쌓은 **검색 신뢰도가 같이 사라진다.** 재개설해도 처음부터 다시다.
- 404 가 반복되면 크롤러가 **그 경로 전체(`/courses/*`)의 재방문 빈도를 낮춘다** — 살아있는 다른 강의의 색인 속도까지 느려진다. 즉 손실이 죽은 URL 하나에 갇히지 않는다.
- 카톡·커뮤니티에 공유된 링크가 마감과 동시에 죽는다.

그리고 우리 도메인에서 **강의는 계속 마감된다.** 그래서 예전 구조는 한 문장으로 요약된다:

> **강의가 잘 팔릴수록 검색 자산이 줄어든다.**

이건 FE 가 라우팅으로 못 고친다 — BE 가 400 을 주는 한 페이지는 `notFound()` 다. 그래서 계약 문제다.

## 정책

### P1. 읽기 축과 행동 축은 다르다 (이 피처의 뼈대)

| 축 | 게이트 | 통과 | 쓰는 곳 |
|---|---|---|---|
| **읽기**(색인 자산) | `CourseService.requirePubliclyReadable` | OPEN + **발행 이력 있는** CLOSED | 공개 상세 |
| **행동**(지금 뭔가를 함) | `CourseService.requirePubliclyVisible` | OPEN 만 | 저장(북마크) 등 |

**읽을 수 있다 ≠ 살 수 있다.** 마감 강의는 상세가 200 으로 열리지만 저장은 400 이다. 클라이언트는 `status` 로 **신청·저장 CTA 를 함께 비활성화**하고 "모집이 마감된 강의예요" 로 바꾼다.

🔴 **공통 조건은 반드시 한 곳에서 공유한다.** 없음·차단(`blocked_at`)·데모가림(`showSeededCourses`)·미승인 강사는 `publiclyExposed` 헬퍼 하나가 건다. 원래 게이트가 하나였던 이유가 그거고(이 도메인은 **두 번** 밟았다 — 차단 강의와 미승인 강사가 상세 URL 로 샜다), 축을 나눌 때 **갈라도 되는 건 상태 하나뿐**이다. 새 공개 표면을 만들면 둘 중 하나를 고르는 것이지 조건을 새로 쓰는 게 아니다.

### P2. 판정은 상태가 아니라 발행 이력이다

`CourseStatus` 전이는 자유라 **DRAFT → CLOSED 직행**이 가능하다. 그건 "마감된 강의" 가 아니라 **한 번도 발행된 적 없는 초안**이다 — 지킬 색인 자산이 애초에 없고, 열면 **강사가 공개를 선택한 적 없는 내용**(가제목·미완성 사진)이 노출된다. 레포의 "존재 숨김" 규약 위반이다.

그래서 `course.published_at`(최초 OPEN 시각, **되돌리지 않음**)이 판정한다. DRAFT 는 발행 이력과 무관하게 계속 400 — 강사가 스스로 내린 것은 내린 상태로 둔다.

⚠️ **이 값을 `datePublished` 로 노출하지 말 것.** V37 백필이 마이그레이션 이전 행에 `COALESCE(updated_at, created_at)` 를 넣었는데 CLOSED 행에선 그게 사실상 **마감** 시각이다. 지금 용도는 불리언 하나뿐이다.

### P3. 거절 사유는 갈리지 않는다

없음·DRAFT·미발행 CLOSED·차단·데모가림·미승인 강사 — 전부 **같은 400 (`-1009`)**. 왜가 갈리면 그 자체로 존재를 알려주는 채널이 된다. 읽기 축을 연다고 이 규칙이 느슨해지지 않는다.

### P4. 마감 강의를 sitemap 에 **새로** 싣지는 않는다

`GET /courses/browse` 는 그대로 OPEN 만 반환한다(`includeClosed` 류 축을 열지 않았다).

- 이슈가 말한 손실은 "**이미 색인된** URL 이 죽는 것" 이고, 그건 상세를 여는 것만으로 해결된다. 크롤러는 자기 색인에 있는 URL 을 sitemap 없이도 다시 가져간다.
- 마감 강의를 sitemap 에 새로 넣는 건 한정된 **크롤 예산을 살 수 없는 페이지에 쓰는 것**이다. 구글의 만료 상품 가이드도 "페이지는 살리되 sitemap 에 계속 두라" 고는 하지 않는다.
- 필요해지면 그때 축을 연다 — 지금 열면 되돌리기가 계약 변경이 된다.

### P5. `lastmod` 는 **모르면 안 낸다**

FE 는 날짜가 없으면 `<lastmod>` 를 **생략**한다(FE 결정 D4). 모르는 값을 `now` 로 채우면 매 시간 "전부 방금 바뀌었다" 고 말하는 셈이라 크롤 예산이 낭비되고, 크롤러가 `lastmod` 자체를 불신하게 된다.

그래서 BE 가 **거짓말 대신 진짜 시각**을 낼 책임을 진다. 의미는 **"이 페이지에 보이는 내용이 마지막으로 바뀐 시각"** 이면 되고, 정확한 감사 로그일 필요는 없다 — 대략만 맞아도 크롤러 판단이 훨씬 나아진다.

#### 무엇이 반영되고 무엇이 안 되나 (과신 방지)

| 응답 | `updatedAt` 이 잡는 것 | **못 잡는 것** |
|---|---|---|
| `CourseCardResponse` · `CourseDetailResponse` | 강의 수정 · 상태 전이 · (콜백으로) 그 밖의 행 변경 | — |
| `InstructorBrowseCardResponse` | 한마디·소개·활동지역(`account_branding`) · 기록 교체 · 자격/종목 승인 변경(`instructor_application`) | **아바타**(`profile_photo` 에 시각 컬럼 없음) · **자격증 이미지**(`application_certificate` 동일) |
| `CommunityPostCard` | 글 본문·제목·분류 수정 | 미디어·태그만 교체한 경우(자식 테이블만 바뀌어 부모 행이 안 더러워진다) |

못 잡는 축은 **의도적으로 남겨 뒀다** — 컬럼 두 개를 더 파는 비용보다 근사 `lastmod` 의 이득이 크고, 이슈가 그 범위를 명시적으로 허용했다. 정확도가 필요해지면 그 테이블에 시각을 넣는 게 정공법이다(자식 변경을 부모로 전파하는 트리거식 우회 말고).

### P6. GEO — BE 가 지는 몫은 "사실을 구조로" 하나다

생성엔진은 **인용할 수 있을 때만 인용한다.** 뭉개진 값(`"35만원부터"`)·모순된 값(같은 숫자가 화면마다 다름)·비어 있는 값은 그냥 안 쓴다. 링크빌딩 같은 게 아니라 **응답 스키마 품질** 문제이고, 그래서 BE 몫이다.

**규칙 넷.** 셋은 이미 레포 규약이라 새로 만든 게 아니라 *같은 규칙이 GEO 에도 값을 한다*는 것을 적어 두는 것이다.

1. **BE 는 문자열을 만들지 않는다.** 가격은 `350000`(number), 시각은 ISO-8601, 상태는 enum. `"15분 전"`·`"35만원"` 같은 표시 문자열은 클라이언트가 만든다. 이 규약이 이미 있었고(커뮤니티 `createdAt` 주석), GEO 관점에서 다시 중요해진다 — 숫자여야 인용되고 비교된다.
2. **토큰 없이 완전해야 한다.** 크롤러·LLM 은 로그인하지 않는다. 공개 상세는 `permitAll` 이고 토큰이 없으면 개인화 필드만 조용히 `false` 가 된다(`bookmarkedByMe`) — **본문이 빠지지 않는다.** 개인화 때문에 본문을 가리는 설계를 새로 만들지 말 것.
3. **같은 사실이 두 표면에서 갈리면 안 된다.** LLM 이 모순을 만나면 인용을 포기한다. 이미 실천 중인 예: 강사 카드의 "강의 N" 은 **강의 둘러보기가 실제로 보여주는 것과 같은 기준**으로 센다(안 그러면 "강의 3" 을 눌렀는데 목록이 0건). 새 집계를 만들 때 기준을 복제하지 말 것.
4. **URL 은 안정적이어야 한다.** 인용은 URL 에 붙는다. 공개 식별자가 순번 id 가 아니라 닉네임 handle 인 것(anti-IDOR 규약)과, 마감돼도 URL 이 사는 것(P1·P2)이 여기서 한 번 더 값을 한다.

#### 지금 인용 가능한 사실 / 없는 사실

`GET /courses/{id}/detail` 은 이미 꽤 좋다 — 가격 · 총 회차 · 위치(이름·유형·지역) · **입장료(이용권 × 평일/주말)** · 장비 · 자격 단체와 레벨 · 강사 자격까지 **구조로** 내려간다. 시안의 단일 `entry` 를 거부하고 이용권×daypart 로 쪼갠 결정이 결과적으로 GEO 에도 이득이었다.

🔴 **두 개가 비어 있고, 둘 다 질문 빈도가 높은 축이다:**

- **일정이 없다.** 공개 상세의 회차에는 **날짜가 없다**(`roundIndex`·설명·위치 후보뿐). "이 강의 언제 해요" 는 검색·LLM 질의의 1순위인데 공개 표면에 답이 없다. 실제 일정은 `availability`(강사 캘린더) ∩ 신청 흐름에 있고 공개 상세와 아직 연결되지 않았다 — [course.md](../architecture/course.md) §6 의 "상세 ↔ 부킹 연동" 이 그 자리다.
- **평점·후기가 없다.** 리뷰 도메인 자체가 v1 과 함께 삭제됐고 재구현 전이다. 없는 값을 지어내지 않는다는 결정(강사 카드에서 평점 슬롯을 비운 것)은 옳지만, **인용 경쟁에서는 불리한 채로 간다**는 것을 알고 가는 것이다.

둘 다 "문서화된 빈칸" 이지 이번에 고칠 것은 아니다. 리뷰·부킹이 붙을 때 이 문단을 근거로 공개 상세에 실을지 판단한다.

#### AI 크롤러 허용 정책은 FE 소유다

robots 의 AI 크롤러 9종 명시 허용(GPTBot·OAI-SearchBot·ChatGPT-User·ClaudeBot·anthropic-ai·PerplexityBot·Google-Extended·CCBot)은 FE 결정 **D2** 다. **BE 는 크롤러를 구분하지 않는다** — User-Agent 로 응답을 바꾸는 건 클로킹이고, 우리 공개 응답은 사람에게든 봇에게든 같다. 나중에 "학습용은 막고 검색·인용용은 연다" 로 가더라도 그건 robots 한 곳에서 하는 결정이지 BE 분기가 아니다.

## 새 공개 읽기 엔드포인트를 만들 때 — BE 체크리스트

FE 문서에 "새 공개 라우트 체크리스트" 가 있는데 BE 쪽 짝이 없었다. 공개 표면을 하나 늘릴 때마다 아래를 통과시킨다.

1. **게이트를 새로 쓰지 않는다.** 읽기 축(`requirePubliclyReadable`)인지 행동 축(`requirePubliclyVisible`)인지 **고르는 것**이다. 공통 조건(차단·데모가림·승인)을 손으로 다시 나열하는 순간 다음 우회로가 생긴다(P1).
2. **"없어짐" 을 400/404 로 만들기 전에 멈춘다.** 그 리소스에 **FE 라우트가 붙는가?** 붙는다면 한 번이라도 공개됐던 것은 **읽기 전용 200 + 상태 필드**를 먼저 검토한다. 죽은 URL 은 되돌릴 수 없는 손실이다(P2).
3. **시각 필드를 넣었는가.** URL 이 생기는 리소스면 `updatedAt` 이 있어야 `lastmod` 를 낼 수 있다. 없으면 크롤러가 재크롤 판단을 휴리스틱에 맡긴다(P5). **엔티티에 `@PrePersist`/`@PreUpdate` 가 실제로 붙어 있는지**까지 확인할 것 — `Course` 가 그게 없어서 신규 행 `updatedAt` 이 null 이었다.
4. **자식 컬렉션만 바뀌는 수정 경로가 있는가.** 있으면 부모 행이 안 더러워져 `@PreUpdate` 가 **안 뛴다** — 교체 지점에서 손으로 찍는다(`AccountBranding.replaceRecords` 가 그 형태).
5. **토큰 없이 본문이 완전한가.** 개인화 필드는 조용히 기본값이어야 하고 401 이면 안 된다(GEO 규칙 2).
6. **사실이 구조인가.** 숫자는 숫자로, 시각은 ISO-8601, 상태는 enum. 표시 문자열을 BE 가 만들지 않는다(GEO 규칙 1).
7. **PII 가 공개 응답에 섞이지 않았는가.** 공개 식별자는 순번 id 가 아니라 handle 이다([security.md](../architecture/security.md)).
8. **`types.ts` 와 이 문서의 결정 히스토리를 같은 PR 에서 갱신했는가.**

## 소유 경계 — 무엇이 BE 결정이고 무엇이 FE 결정인가

두 레포에 걸쳐 있어서 이슈가 올 때마다 헷갈린다. 기준은 **"그 결정이 응답 계약을 바꾸는가, 렌더링을 바꾸는가"** 다.

| 결정 | 소유 | 근거 |
|---|---|---|
| 무엇이 공개인가(게이트·상태코드) | **BE** | 존재 숨김은 보안 결정이지 표현 결정이 아니다 |
| `lastmod` 의 원천 시각 | **BE** | 우리만 안다. 없으면 FE 는 생략할 수밖에 없다 |
| 사실의 구조(필드·타입·enum) | **BE** | 계약이다. GEO 품질의 바닥 |
| 공개 URL 식별자(handle vs id) | **BE** | anti-IDOR 규약 |
| sitemap 구성·순회·ISR 주기 | **FE** | BE 는 모수 API 만 연다 |
| robots · AI 크롤러 허용 | **FE** | BE 는 크롤러를 구분하지 않는다 |
| canonical · 메타데이터 · og:image | **FE** | 렌더링 |
| JSON-LD 필드 채우기 | **FE** (원천 사실은 BE) | 스키마 매핑은 표현 계층 |
| IndexNow · on-demand revalidate | **FE** | BE 에 변경 통보 훅이 없다(아래 미해결) |
| **어떤 URL 이 sitemap 에 들어갈 자격이 있나** | **공동** | BE 가 모수를 정의하고(예: `browse` = OPEN 만) FE 가 그중 고른다. P4 가 이 칸의 사례다 |

## 미해결 / 확장

- 🟡 **`profile_photo`·`application_certificate` 에 시각 컬럼이 없다** — 강사 프로필에서 가장 눈에 띄는 변경(사진 교체)이 `lastmod` 에 안 잡힌다. 필요해지면 두 테이블에 `updated_at` 을 넣고 강사 카드 합성에 더한다.
- 🟡 **`CourseRound`·`RoundVenue` 변경의 전파** — 회차/위치만 바꾼 수정은 서비스가 명시적으로 `updatedAt` 을 찍어 반영되지만, 그 밖의 자식-only 경로가 생기면 같은 함정을 밟는다(부모 행이 안 더러워지면 `@PreUpdate` 가 안 뛴다).
- 🟡 **IndexNow / on-demand revalidate 는 FE 소유** — BE 가 변경을 알리는 훅(웹훅)은 없다. 새 글·새 강의의 **즉시 통보**가 필요해지면 그때 논의(지금은 sitemap ISR 1h + 크롤러 주기).
- 🟢 **저장 목록에 마감 카드 복원** — 재료(`status`)는 나갔고, 목록에 다시 넣을지는 FE 결정.
- 🔴 **공개 상세에 일정이 없다**(GEO P6) — "언제 하나요" 에 공개 표면이 답을 못 한다. `availability` ∩ 공개 상세 연동([course.md](../architecture/course.md) §6)이 붙을 때 함께 판단.
- 🟡 **평점·후기가 없다**(GEO P6) — 리뷰 도메인 미재구현. 없는 값을 지어내지 않는 건 옳지만 인용 경쟁에선 불리한 채로 간다.
- 🟡 **llms.txt · AI 크롤러별 차등 정책** — 지금은 9종 전부 허용(FE D2). "학습용은 막고 검색·인용용은 연다" 로 갈 이유가 생기면 robots 한 곳에서 하는 결정이고 BE 분기가 아니다.
